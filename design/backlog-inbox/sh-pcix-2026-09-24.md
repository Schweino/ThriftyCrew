## invoke-pipelinecommit now resyncs the shared index for exactly the paths its commit carried

`DONE` `queue-7`

**What changed.** `Sync-PipelineSharedIndex` runs after a commit LANDED and after the private index is released. It
lists the commit's own paths with `git diff-tree --no-renames -z <parent> <commit>` and resets exactly those in the
checkout's real index (`git --literal-pathspecs reset -q --pathspec-from-file --pathspec-file-nul`): never the working
tree, never a path outside the commit. `--no-renames` matters: a delete-plus-identical-add is a rename to git, and the
rename form names only the new path, so the deleted one kept its stale entry (the `RD` row below). When HEAD is no
longer the commit this call made, it resets nothing and says `index resync SKIPPED`; when the reset cannot run (another
process holds `index.lock`) the verdict carries `index resync FAILED` and the commit still classifies `committed`.

**Reproduced before the fix, in the self-test's own temp repo** (the new end-to-end block, base blob above): after a lane
commit that modified, deleted, added, delete-plus-identical-added and added a path with a space and a non-ASCII letter,
`git status` read `MM lane/out/a.json | D  lane/out/café y.json | AD lane/out/gone.json | RD lane/out/moved-from.json |
D  lane/out/new.json` plus `??` for each added file; `git checkout-index -a` brought both deleted files back on disk; and

for six changes, which is unchanged behaviour).
