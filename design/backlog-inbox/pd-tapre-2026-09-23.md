## expected-live-red cannot see the food-category live twin since it moved to the live-red tally

`OPEN` `queue-pd-tapre` `2-WAY` `RUNG1 BUILD`

**Source.** Lane `tapre` of design/PLAN-push-derived-conflicts-2026-09-23.md (W8.5), 2026-09-23, found while reading
`ops/prepush-test-auditors.ps1` for W8.5 and measured with a read-only scratch probe over origin/main's copies of that
file and `grocery/test-auditors.ps1` (its four functions lifted by AST, then driven).

**What is wrong.** Since 2026-09-20 (queue 2026-09-19-ae9df2) the food-category live twin reports through `Live(...)`,
so its failing line reads `LIVE-RED  LIVE-TWIN food-category failed (rc=2) - ...`. `$script:LiveCaseRx` was widened to
`(?:Bad|Live)` so the case is still found as a ruling case, but `Resolve-ExpectedLiveReds` strips only `^FAIL\s+` from a
new failing line before it tests `StartsWith(<the case's prefix>)`, and does the same before it reads the case's exit
code. So the real line never matches. Measured: a `LIVE-RED` line built from the real prefix was not recognised (the
function returned untouched with no line), and the same text with a `FAIL` tag was recognised. The effect is that a
push adding a category-excludes ruling against a product still on the board is refused as an ordinary new failing
case, with no paired run: the "Teach the gate" deadlock of 2026-09-19 is back for food-category rulings. The
known-wrong twin still reports through `Bad(...)` and is unaffected.

**Why the suite is green.** Every EXPECTED-LIVE-RED fixture builds its lines as `'FAIL  ' + <prefix>`, so no case ever
hands the function the tag the harness really prints.

**What W8.5 does and does not change.** Its PREEXISTING trace matches `LIVE-RED` lines to `Live(...)` calls by tag, so a
food-category live red that main ALREADY shows is judged at the base and is not refused. A red the push's own ruling
causes is not PREEXISTING (it is green at the base), falls through to EXPECTED-LIVE-RED, and is refused as above. W8.5
left `Resolve-ExpectedLiveReds` byte-identical on purpose (its CLEAN TWIN is "decides exactly as before").

**First rung.** Strip the harness's tag (`^(FAIL|LIVE-RED)\s+`) in both places `Resolve-ExpectedLiveReds` reads a line,
and add a MUST FIRE whose line carries the `LIVE-RED` tag, beside the `FAIL` ones. Two-way: a revert restores today's
refusal, never a wrong acceptance, because the paired run still decides.
