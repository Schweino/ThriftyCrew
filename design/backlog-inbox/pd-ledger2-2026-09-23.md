## the push ledger's session field groups a parallel run only if sibling lanes share one host session id, which one lane cannot show

`OPEN` `2-WAY` `RUNG1 MEASURE`

**Source.** Lane pd-ledger, W0.1 of design/PLAN-push-derived-conflicts-2026-09-23.md, 2026-09-23, carried into its
rebuild on the fetch-and-rebase-first push-main (W0.1R, lane pd-ledger2) because the first build never landed.
`Get-ChildItem env:` inside that spawned build lane read `CLAUDE_CODE_CHILD_SESSION=1`,
`CLAUDE_CODE_HOST_SESSION_ID=local_<guid>` and `CLAUDE_CODE_SESSION_ID=<guid>`, and no orchestrator run id of any other
name. ops/push-main.ps1 writes the row's `session` from the host id first and the lane's own id second, and
`session_var` names which one supplied it. The rebuild lane, spawned by a workflow script, read the same three
variables, and its `CLAUDE_CODE_SESSION_ID` is the id in its own scratchpad path, so that one is per lane. Neither lane
recorded its host id's value, so the two cannot be compared after the fact.

**What is not known.** That every lane of one orchestrated run carries the SAME host id was read from one lane, not
compared across two. W0.3's parallel-run test (at least 4 distinct checkouts sharing one `session` inside 2 hours) rests
on it: if each lane's host id differs, no parallel run is ever found and the bar that needs one reads an agreeing zero.

**First rung.** After this wave's lanes land, read their push-main rows and count distinct `session` values across the
lanes' checkouts. One value confirms the assumption; one value per lane means the test must key on something else.

## a child's stdin written through process.standardinput starts with a utf-8 byte order mark on this box

`OPEN` `2-WAY` `RUNG1 DOC`

**Source.** Found by ops/push-main.ps1's own self-test, lane pd-ledger, 2026-09-23. The first `change_id` reader copied
`git diff`'s stdout into `git patch-id --stable` through `Process.StandardInput.BaseStream`, and patch-id printed nothing
for a diff that bash's pipe hashed at once. Measured the same day: `[Console]::InputEncoding` is utf-8, code page 65001,
with a 3-byte preamble, and a child powershell fed four bytes through that stream read `EF-BB-BF-64-69-66-66`. The
StreamWriter .NET wraps a redirected stdin in writes the preamble when it is created, so the child's first line begins
with a BOM and patch-id never sees `diff --git`.

**Reach.** Census the same day over the 841 tracked `.ps1`: 0 write a child's StandardInput (positive control: 37 use
RedirectStandardOutput), so there is no live site; push-main pipes through cmd.exe instead, and the W0.1R rebuild kept
that. The knowledge store held nothing on it (knowledge-search: no match for `StandardInput` or `InputEncoding` in 2292
sections).

**First rung.** One line beside the native-exe notes in .claude/rules/ops-and-gates.md, or a section in
software-craft/applies-here.md's "PowerShell 5.1 answers wrong instead of erroring", so the next pipe between two child
processes is not written this way.

## the w0.1r row now carries six fields the convergence probe does not read yet, and four of its bars read wrong without them

`OPEN` `2-WAY` `RUNG1 BUILD`

**Source.** Two skeptical reviews of W0.1R (lane pd-ledger2, 2026-09-23), each finding driven through the real
ops/push-main.ps1 from a temp mirror. The row side is fixed in ops/push-main.ps1 with a fixture for each field; the reader
side is ops/probe-push-convergence.ps1, a harness of design/MEASURE-push-convergence-2026-09-12.md, so it is left to the
probe's lane, as the phase-label finding above was.

**What the probe should read, one line per field.**
- `conflict_target` (the FETCH_HEAD of the sync whose rebase conflicted). Resolve-TcPpcConflictAncestry takes the grant
  as the collider's side for every phase but preflight, and for a CATCH-UP conflict (round 2 or 3) the grant is the
  previous take's in-lock remote, which that rebase never saw. The review's harness named the wrong collider and scored
  B1(b) BBad=1 where the truth is 0. Read conflict_target first, then the current fallback for rows without it, and add a
  MUST FIRE catch-up-conflict row (the push-main fixture's shape: preflight X, grant M1, target Y) that names Y.
- `subject_shas`, `subject_count` and `head_ref`. subjects_sha is one hash over the whole subject set, so the
  housekeeping lane (checkout agent-a49021947d73d02ed, three attempts on 2026-09-23, 09:34 to 10:48Z) is three changes
  under W0.3b's key: each amend rewrote a subject, and its own rebase dropped a commit a sibling had landed. Link
  consecutive unlanded attempts in one checkout by the same head_ref or by any overlap in subject_shas, up to the
  landing, and keep subjects_sha for the exact match. Fixtures: that lane's real subject sets, and a lane that ADDS a fix
  commit after a red. Until then B6(a), B6(b), B10 and the first-attempt share read low or fast for free.
- `reject_rc` (1, 3, or null, read off the hook's BLOCKED line). Test-TcPpcIsRed scores a push-rejected row by its class
  alone, so an in-lock could-not-evaluate of run-gates or test-auditors (slot contention, the planned degrade path)
  counts as the change's own red and is excluded from B6(a). A 3 is neither a red nor a pass; a MUST NOT FIRE keeps an
  exit-1 row a red. B16's test-auditors count should split on it too.
- `hook_ta_scope` ('full', 'selective <n> of <m>', or null). B11 is defined as FULL test-auditors runs inside the lock,
  and hook_ta 'ran' counts a selective run the same way. State which one the baseline of 10 of 84 counted.
- `conflict_scope` 'none-unmerged'. A rebase that failed without stopping (an index.lock) still writes outcome
  refused-rebase-conflict, now with conflict_files [] and this scope. Get-TcPpcList returns an empty list for both null
  and [], so section 6 counts these rows as pre-W0.1 and they reach B1(b)'s "at least 10 conflict rows". Ask whether the
  field is PRESENT (null is pre-W0.1), not how long the list is, and keep these rows out of B1(b) until W2.1R names them.

**Two formula points, not fields.** B8 adds catchup_sec to every push-main row on top of (row time minus run start) for
refused rows, which counts a refused row's round-2 legs twice: add catchup_sec only for rows outside the first term. And a
dry run takes the lock and records a real lock_held_ms and lock_wait_ms_total (a fetch and a rebase with no push); only
Get-TcPpcChangeSet skips outcome dry-run, so the lock-hold section (B3's input) and the per-lock-taken-row denominators
(B3, B11) count it. Drop dry runs there or print them as their own stratum.

**First rung.** In the probe's lane: read the six fields above with a fixture each, fix the two formulas, and re-read the
