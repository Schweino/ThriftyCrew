## test-auditors pass records in the shared git directory are never pruned, and schema 2 makes each one about 70 kb

`OPEN` `queue-pd-ta` `2-WAY` `RUNG1 BUILD`

**Source.** Lane `ta` of design/PLAN-push-derived-conflicts-2026-09-23.md (W0.4), 2026-09-23. Measured that morning
in the shared git directory (`git rev-parse --path-format=absolute --git-common-dir` from a linked worktree): 91
`tc-test-auditors-pass-*.json` files, 82 of them last written more than 6 hours earlier, the oldest at
2026-09-18T18:18:39Z, 144,798 bytes in all, beside 119 checkouts in `git worktree list`. Only
`ops/prepush-test-auditors.ps1` reads or writes them (a grep of the tree for the file name and for
`Read-TaPassRecord`), and nothing deletes one except that script's own withdrawal after a run that did not pass.

**What is wrong.** One file per checkout root, named by a hash of the root, so every worktree ever pushed from leaves
one behind when it is removed. W0.4 adds a schema 2 file (`tc-test-auditors-pass-<h>.schema2.json`) beside each old
one, and a schema 2 record carries the key's input rows: 71,392 bytes for a worktree with 631 rows, against 255 to
5,619 bytes for the schema 1 records listed. At the same count that is about 6.5 MB, and the count only grows.

**What a prune must keep.** A record older than the reuse limit (`$script:PassMaxAgeHours`, 6 hours) can never be
REUSED, but since W0.4 the newest schema 2 record of a LIVE checkout is also what names the input that moved the key
(`TA-KEY-MOVED`), at any age. So an age rule alone would turn every push made more than 6 hours after the last pass
into `kind=no-record`. The first rung: delete a schema 1 file older than 6 hours (no copy of the script at or after
W0.4 reads one, and an older copy could not reuse it), and delete a schema 2 file whose own `root` row names a
directory that no longer exists. Both are 2-way: a deleted record costs one full test-auditors run in a checkout that
still exists, never a wrong verdict.
