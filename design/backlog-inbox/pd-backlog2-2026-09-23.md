## the declared lock order does not name the backlog merge task's zero-wait run lock, the first lock held across a push-main run

`OPEN` `queue-7` `2-WAY` `RUNG1 DOC`

`ops/run-backlog-merge.ps1` takes `Global\tc-backlog-merge-run` with a ZERO wait and holds it across the merge's ledger
lock and the push lock `ops/push-main.ps1` takes. Because it never waits it adds no wait-for edge and cannot join a
deadlock, the same argument the plan makes for push-main's per-checkout guard (W2.1, level `0a.` in W6.1 step 7). But
`.claude/rules/ops-and-gates.md`'s "THE LOCK ORDER IS DECLARED, OUTERMOST FIRST" does not list it, and that rule asks
for the first nesting of a pair to be named. The script's header names it; the rules file should too, beside `0a.`
when W6.1 writes that list.
