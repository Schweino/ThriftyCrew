## a lone pscustomobject has no .Count under PS 5.1, so a window of exactly one run read as N=0

`OPEN` `queue-7` `2-WAY` `RUNG1 DOC`

**Found by the report's own B3 case on 2026-09-23.** A function returned `@(... | Where-Object ...)`; with exactly one
match the pipeline unrolled it to a single [pscustomobject], and `(Get-Thing).Count` read `$null`, so one armed run
counted as 0 (`defects=1 n=0`). `([pscustomobject]@{a=1}).Count` is `$null` in Windows PowerShell 5.1 (PowerShell 6.1
added the intrinsic member to it). The estate's rules name the neighbours, `@($null).Count` is 1 and a comma-returned
array wrapped inline counts 1, and not this one. The fix is the comma return (`return , @(...)`), then assign before
wrapping. **First rung:** a line in `.claude/rules/ops-and-gates.md` beside the `@(Get-Thing ...)` rule, or a memory.
