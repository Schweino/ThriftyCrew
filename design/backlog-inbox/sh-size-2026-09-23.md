## the plan's W2.1 incident fixture does not reproduce a refusal, so the lib's incident cases use the 07:00 log's totals

`OPEN` `queue-sh-size` `2-WAY` `RUNG1 DOC`

**Source.** The same lane and day. W2.1's first fixture reads "09-22's refused run recorded 10 files / 13.5 MiB
within-caps, and this run's own 21 files / 11.25 MiB are admitted together; today's gate refused the sum". 13.5 + 11.25
is 24.75 MiB, which `[math]::Round(24.75, 1)` makes 24.8, under the 25 MB cap, and 31 files is under 300. So today's gate
ADMITS that sum, and the case could not show the thing it claims.

**What was built instead.** The lib's self-test uses the 07:00 refusal's own totals, 40 files / 28.8 MB
(`capture-run-ad-2026-09-23.log:67` as the plan quotes it), split as 19 carried files / 17.5 MiB plus 21 own files /
11.25 MiB (28.75 MiB, which rounds to 28.8), and the 08:00 refusal's 51 files / 43.3 MB as two carried records plus 11
own files / 14.5625 MiB (43.3125 MiB). The split between carried and own is chosen, not measured, and the case text says
so. What is left: plan section 6 W2.1 should be corrected to these numbers, or to any pair that sums over 25 MB.

## the carry ledger's schema has one field the plan does not list, and W1.2 and W2.2 should read it

`OPEN` `queue-sh-size` `2-WAY` `RUNG1 READ`

**Source.** The same lane and day. `<git common dir>\tc-commit-carry.json` lives in the COMMON dir, which every linked
worktree shares, so a hand run of capture-run in a worktree would record paths that a byte-equal untracked file in the
main checkout could then be carried under. Each run therefore carries `checkout` (its toplevel, full and lower-cased, the
key `lib/pipeline-commit.ps1` already uses), and `Read-TcCommitCarry -Repo` returns only that checkout's runs, counting
the others. Fixtured as MUST NOT FIRE "a run another checkout wrote is not returned for this one"; the mutant that drops
the filter went red in that case.

**For W2.2.** Call `Read-TcCommitCarry -Repo $repo` (print its `why` when `ok` is false: that is today's gate, not an
error), `Test-CarriedCommitSize -Added ... -RunStart $script:RunStart -Records $read.runs -Now (Get-Date)`, print
`Format-CarriedCommitSize`, and on a run that does not commit `Add-TcCommitCarry -Repo $repo -Run <id> -Kind $Kind
-Started $script:RunStart -Verdict $result.verdict -Files $result.own_files` inside a try/catch (it throws on a lock
timeout, having written nothing). `-Kind` and `-Verdict` are case-sensitive sets. **For W1.2**, a run row's
`recorded` is ISO 8601 UTC and `checkout` separates the main checkout's runs from any worktree's.
