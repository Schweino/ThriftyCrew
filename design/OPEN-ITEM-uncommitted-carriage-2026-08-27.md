# OPEN ITEM: 39 carriage verdicts exist only on this PC, and no job will ever commit them

Date: 2026-08-27. Raised while checking a hand-off from the recipe-hunter session (thriftycrew-4a),
which found `grocery\carriage.json` and `grocery\ingredient-queue.json` dirty and correctly declined
to sweep another process's work into its own commit. Read-only investigation; **nothing was changed,
committed or discarded.** This file records what is there and the three questions an owner has to
answer.

## 1. The measurement

`grocery\carriage.json` at HEAD (3f598108) carries **20** bids. The working tree carries **59**.

- **39 new entries, every one a `CARRIED` verdict** — a store, an item, a size, a price.
- **2 changed entries**: `parmesan-cheese` and `green-bell-pepper`.
- `as_of` on the new ones: **2 from 08-25, 29 from 08-26, 8 from 08-27**. Across all 59 the spread
  runs 2026-08-11 to 2026-08-27.
- By store: Fareway 11, Baker's 10, Aldi 9, Sam's Club 4, Family Fare 2, Walmart 2, Hy-Vee 1.

So this is **not one session's leftovers**. Only 8 of the 39 belong to today's run. The rest were
written by at least two earlier processes on 08-25 and 08-26 and have been sitting uncommitted
since — through a 07:00 pipeline run, and through two agent sessions that each looked at the tree
and left them alone.

The other dirty files, for completeness: `ingredient-queue.json` 95 -> 97 items,
`sale-without-ad.json` 228 -> 193 items (a **shrink** of 35, so entries were removed, not added),
`board-price-overrides.json` changed within its 5 keys, `notify-log.txt` +1 line.
`out\logs\capture-run-status.json` is the only one that will resolve itself — it lives under
`grocery/out`, which the 07:00 job does stage.

## 2. Why nothing has picked them up, and why nothing will

`grocery\capture-run.ps1` stages an explicit path list and never `git add -A` (its own comment at
line 526 says so, changed 2026-08-22 after a blind add swept half-finished work). The list is
`grocery/out`, the ad/alert/ff-sweep logs, `ad-schedule.json`, `price-history.json`,
`product-urls.json`, `sale-windows.json`, `rollback-first-seen.json`, `graph/identity`,
`graph/provenance`, plus a SERVED set gated on a chain verdict the ad run never writes.

**`carriage.json`, `ingredient-queue.json`, `board-price-overrides.json`, `sale-without-ad.json` and
`notify-log.txt` are on none of those lists.** They are regenerated by the pipeline and committed by
nobody. That is precisely the last-mile failure `capture-run.ps1`'s own comments record twice
already — `public\board.json` rebuilt daily against a four-day-old bot commit, and
`graph\provenance` JSONL left untracked while 191 MB of cookies was kept. This is the third instance
of the same shape, and it is the one carrying live prices.

## 3. Why it matters that they are prices

Carriage verdicts are read by the cost engine and by the publish gate. A `CARRIED` verdict that
exists only in one working tree means:

- a fresh clone (and the cloud daily, which clones clean) prices those 39 commodities differently
  from this machine;
- the difference is invisible in `git log`, because the file has not changed in the record since
  2026-08-25;
- and it is **not recoverable** if the tree is ever cleaned. `grocery\push-data.ps1:17` runs
  `git checkout --` over five grocery files before its `git add -A` — carriage is not among those
  five, so it is not at risk from that path specifically, but any `git checkout`/`clean`/`reset
  --hard` in this repo destroys all 39 silently.

One of the two changed entries is a substitution, not a refresh:

```
parmesan-cheese  HEAD:  Reggano Grated Parmesan Cheese 8 OZ          as_of 2026-08-24
parmesan-cheese  NOW :  Reggano Grated Parmesan Romano Cheese 8 OZ   as_of 2026-08-26
```

Same store, same price, **different product** — a Parmesan-Romano blend standing where straight
Parmesan stood. Whether that is a correct re-verification of what Aldi actually stocks or a
mis-promotion is exactly the kind of thing that should not be decided by whoever happens to commit
next. (`green-bell-pepper` is a genuine no-op: same item, same 0.79, only `as_of` moved.)

## 4. The three questions, for an owner

1. **Are the 39 promotions trusted?** They were written by processes that ran on 08-25/26/27 and
   nobody has reviewed them since. If yes, they should be committed as a deliberate act with a
   message that says whose run produced them. If not, they should be regenerated, not deleted by
   accident.
2. **Is the `parmesan-cheese` substitution correct?** Parmesan -> Parmesan Romano changes what a
   reader buys. It needs a yes or a no, not a commit.
3. **Should these five files be added to a staging list, or is being uncommitted the design?** If
   carriage is meant to be machine-local state, that should be written down and it should be
   `.gitignore`d so nobody keeps rediscovering it. If it is a durable record — and a `CARRIED`
   verdict reads like one — then something has to stage it, and today nothing does.

## 5. What was deliberately not done

Not committed: they are another process's unreviewed pricing verdicts, and committing them would
put 16 days of three sessions' work into the record under a fourth session's name and message.
Not discarded: they are live facts and 39 of them are the only copy.
Not repaired: adding these paths to `capture-run.ps1`'s staging list is a change to the daily
pipeline's blast radius and belongs to whoever owns that chain, after question 3 is answered.
