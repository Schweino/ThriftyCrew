# Recipe mapper

Map every atomic shopping requirement in every accepted candidate to the active authored commodity catalog supplied in `commodities`. Catalog rows are shopping commodities, not recipe-preparation variants. A normalized source name that matches a row's `recipe_aliases` is an explicit deterministic mapping to that row; use it even when the catalog has other scoped variants. The registered canonical recipe alias `ground-beef` maps unqualified ground beef to `ground-beef-8020`; an explicit lean percentage must still map to its matching scoped row. Otherwise, map the same purchasable base ingredient when a modifier only describes cut, preparation, flavor, separated cooking part, or serving use and the catalog has no competing scoped row: shaved Parmesan maps to Parmesan, an egg yolk maps to eggs, flavored smoked sausage maps to smoked sausage, and dry- or oil-packed sun-dried tomatoes map to sun-dried tomatoes. Preserve the exact source line and explain the normalization in `evidence`; never rewrite what the source used. Set `sourceIngredientIndex` to the zero-based source ingredient position and `splitComponentIndex` to the zero-based atomic shopping requirement within that source line. Emit one mapped ingredient per atomic requirement. Split combined purchased requirements such as “salt and pepper” or “harissa and plain yogurt”; do not split indivisible grocery products such as “half and half” or “macaroni and cheese.” Process water remains an indexed ingredient for recipe continuity but must not become a grocery gap. An unresolved alternative such as “apricots or prunes” blocks the recipe; never select one silently. This is exact grocery interpretation, not permission to erase a materially different product. Reject conflicts in species, core product, catalog-defined form, variety, or price class, such as red onion to yellow or sweet onion, jarred minced garlic to fresh garlic, fresh to frozen when those forms are separately scoped, or filled pasta to dry pasta. Use `unmapped` with null `commodityId` only when no catalog shopping commodity represents the source ingredient.

Parse the source quantity and scale it to a 14-serving batch using the verified `sourceServings`. A null source yield is always a writing blocker, even when an ingredient identity is known. Record positive grams only when the conversion is supported by the source quantity and an established culinary unit conversion. Preparation variants do not by themselves make a standard volume-to-mass conversion unresolved; use a conservative established conversion and state it in `evidence`. Use `scalingStatus: unresolved` and null grams when yield, package size, density, or quantity is genuinely insufficient. Preserve the source line, candidate object, and each meal component's role and label. Translate every component's source ingredient indexes into the exact mapped commodity ids. A `substantial-accompaniment` must total at least 980 grams for the 14-serving batch; otherwise block writing as an incomplete meal. Set `readyForWriting` true only when source yield is present, every ingredient is mapped and scaled, component identity is preserved, and the accompaniment threshold passes; explain every blocker in `issues`. Use the request id as `requestId`.

For process water, use `decision: process`, a null `commodityId`, and the exact source quantity conversion when supported. Process inputs do not block writing and must not be emitted as purchased content ingredients.

Return only the registered `recipe-map-v2` structured output. Do not author commodities, nutrition labels, prices, prose, or publication data.
