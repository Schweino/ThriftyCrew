## 1. Each-unit commodities the engine cannot price

### 1.1 Root cause, one level up

`Get-UnitPrice`'s `each` branch (`compare-deals.ps1:687-733`) prices an each-commodity only when it
can find a PACK COUNT in price_text, size_text or the name; a row whose only stated size is a weight or
an area falls through to `return $null` ("bare package price with unknown count -> drop"). That refusal
is correct for produce sold by the bag (a 2 lb bag of kiwi is an unknown number of kiwis) and wrong for
a packaged good (a 14 oz loaf is one loaf). The engine cannot tell the two apart because nothing in
`commodities.json` says which kind of each-commodity a given id is. The unit vocabulary is also split
across three lists that drifted: `Convert-ToUnit 'each'` accepts `head|loaf|bunch`, the bare-token list
in `Get-SizeAmount` (line 244) does not, and the each-branch's own regex (line 730) accepts `bunch(es)`
only, patched 2026-08-31 for green onions. Hy-Vee's "Bud Iceberg Lettuce | head | $1.97" is unpriced
today for exactly that reason. `sq_ft` is absent from `Convert-ToUnit` entirely (c360aa06 measured
this on 09-05 and deliberately changed nothing).

The CLASS is "a commodity's unit says how to compare, but not how to read a row that states a
different measure", and the same class produced garlic-bread's `pack_is_package` declaration on
2026-07-30. The stop is a per-commodity declaration of how a weight-only or area-only row is to be
read, plus one vocabulary the three readers share (`unit-vocabulary-lib.ps1` already derives the
vocabulary by parsing `Convert-ToUnit`'s source; it should be the source instead).

### 2.4 Ruling order and the per-cell mechanics

Work the worklist nearest-floor-first as it is written, because that ordering surfaces the pure floor
errors, but the ACTION per row is one of exactly four:

- **LOWER-FLOOR** (class 1, 2+7): edit that commodity's `band_min` in `commodities.json` and record
  `band_min_set_under: "<row name> <store> <per-unit> <date>"` beside it. Before the edit, list EVERY
  row at EVERY store that the new floor admits (from the flagged file: rows with unit_price between
  new and old floor for that id), and rule each one by 3-6. A floor move with an unruled admitted row
  is not shippable.
- **LEDGER** (class 3, 5): `add-known-wrong.ps1` with the verdict (`wrong-product` or `wrong-form`),
  evidence naming the floor that was hiding it, so the row cannot return when the floor moves.
- **PARSE-FIX** (class 4): a parser change with its own must-fire (the frozen row) and clean twin
  (the same grammar meaning the opposite thing; canned-pineapple's twin is the Sam's hummus singles
  pack, where "16 ct 2.5 oz" really is 40 oz).
- **BRAD** (class 6): held in the worklist with a `needs_ruling` note until ruled.

Every floor edit is measured the same way as area 1.5: scratch compare-deals with the edited
commodities file, diff cells by name, positive control = the cell the edit was made for MUST move
(maple-syrup Walmart 0.0811 -> 0.0789; soda Baker's 0.0312 -> 0.0148). Then `audit-band-censorship`
must report a LOWER cell count and the ratchet must tighten; a run that reports 50 after a floor move
did not read the new board.

### 2.5 The class stop

- `band_min` provenance: a field per commodity naming the row it was set under. New commodities via
  `new-commodity.ps1` require it. An audit (`audit-band-provenance.ps1`) lists floors with no provenance
  as a ratchet from today's count downward, and hard-fails a floor whose provenance row is now BELOW
  the floor (the floor has clipped its own evidence). Must-fire: fixture commodity with band_min 0.08
  and provenance row at 0.0789 -> finding. Clean twin: provenance row at 0.081 -> silent. Second twin:
  no provenance on a commodity in the baseline -> counted, not failed.
- The band-censorship ratchet (already live, baseline 50) stays the standing detector for the class.
- Wrong-product duty is explicitly the ledger's: every LOWER-FLOOR ruling ships with its LEDGER
  entries in the same commit, and `audit-known-wrong` is in the publish path already.

### 2.6 Not proposing, and why

- A blanket tolerance below the floor: publishes AriZona as half-and-half the same day (the brief's
  own example, and the ledger has no entry for it).
- Auto-admitting a below-floor row when the store's own unit price agrees: the AriZona parse is right,

- Removing floors on each-commodities: the universal `$FLOOR` already exempts `each`; the inline
  bands are the only net those 100 commodities have.

### 2.7 Brad's calls

## 3. push-data.ps1 stages the whole tree

### 3.1 Root cause, one level up

`push-data.ps1` was written in July for a tree that held only raw store inputs, and its safety rested
on that assumption. The assumption stopped being true when agents began editing code in the real
working tree, and nothing re-checked it. Three defects in 32 lines:

1. `git add -A` with no pathspec (line 18), where `capture-run.ps1` already carries the correct
   pattern: an explicit `$inputPaths` / `$servedPaths` ownership list, `git add -A -- $paths`, and a
   commit-size gate. push-data is the one remaining sweeper in the tree (`daily.yml` also sweeps, in a
   throwaway cloud clone, which is fine).
2. `git commit ... 2>&1 | Out-Null` (line 21) discards the commit's exit code. The pre-commit hook
   installed on 09-05 can refuse the commit and push-data will not notice; it then runs `git pull` and
   `git push`, pushes whatever was already committed, and prints "raw store inputs pushed".
3. `git checkout --` over five files (line 17) DISCARDS uncommitted local edits to smp-feed.json,
   published-board.sig, last-visibility.txt, price-history.json and alert-state.json, silently, before
   anything else runs. That is data loss, not misfiling.

A fourth hazard sits beside it: every bot commit here is authored as Brad (`Schweino`), so the git
log cannot say which process made a commit. That is why the 14:40 owner cannot be named today
([[name-the-owner-from-process-shape]]).

The CLASS is "an automated commit primitive that stages by sweep or commits a shared index", and the
estate has paid for it four times (2026-07-23 walmart flood, 2026-08-22 4,388-file profile commit,
2026-08-25 F2 unit in 0c47012c, 2026-09-05 3c44d0c1). The stop is that no automated commit may touch
a path outside its declared ownership list, enforced at the hook, and that automated commits identify
themselves so the hook can tell them from a session.

### 3.2 Blast radius

Measured as commits, not cells: 3c44d0c1 carried 192 `.ps1` files mid-edit, 27 of which threw at
startup, and main held that for 59 minutes (14:40:39 to e1acec2a at 15:39:29). No board cell was
changed by the sweep itself; the daily chain did not run in that hour. The risk is the next occurrence:
push-data is still callable by any session or agent, four disabled scheduled-task prompts still tell
an agent to run it, and `weekly-post-capture.ps1 -Phase links` (the weekly agent's path) still ends in
it.

### 3.3 Proposal, in order

1. **Rewrite push-data.ps1 to stage by ownership list.** Import the `$inputPaths` list from
   capture-run (lift it into a shared `lib\bot-paths.ps1` so there is one list, not two hand copies;
   the estate's own rule about pasted twins), `git add -A -- $paths`, check `$LASTEXITCODE` after
   `git commit` and STOP with a named failure when the hook refuses, remove the `git checkout --`
   discard (if a cloud-owned file needs resetting, `git checkout -- <file>` only when `git status`
   shows it clean of local edits, otherwise report it). Author the commit as `smp-pipeline-bot` (the
   identity capture-run already uses) so the log names the process.
2. **Private index for every bot commit.** Both push-data and capture-run's publish stage run their
   `git add` and `git commit` under `GIT_INDEX_FILE` pointing at a temp index seeded from HEAD
   (`git read-tree HEAD`). A bot commit then cannot carry anything a session left staged, and cannot
   disturb the session's index. This is the class stop for the 2026-08-25 shape, which explicit
   staging alone does not fix because `git commit` without a pathspec commits the whole index.
3. **Hook: refuse an out-of-scope bot commit.** Extend `ops\hooks\pre-commit`: when the author is
   `smp-pipeline-bot` (or `TC_BOT_COMMIT=1` is set), any staged path outside `lib\bot-paths.ps1`'s
   list refuses the commit and names the paths. Sessions are unaffected. Keep `--no-verify` as the
   loud bypass it already is; `audit-hook-installed` already proves the hook is present.
4. **Retire the sweep callers' instructions.** The four disabled scheduled-task SKILL.md files that
   say "run push-data" get a line saying it is gone; `weekly-post-capture.ps1` calls the rewritten
   script (or capture-run's publish stage directly).
5. **Static guard.** `audit-git-sweepers.ps1`: no tracked script may contain `git add -A` or
   `git add .` without a `--` pathspec, allowlisted for `daily.yml` (throwaway clone) and the
   fixture repos in `test-commit-size-gate.ps1`. Wire into `run-gates.ps1`.

### 3.4 Must-fire and clean twin

- Ownership staging (1): in a fixture repo (extend `test-commit-size-gate.ps1`, which already builds
  one), dirty a `.ps1` and a `grocery/out/regular/*.json`; run the new push-data; the commit MUST
  contain the json and MUST NOT contain the `.ps1`. Clean twin: with only owned files dirty, the
  commit contains all of them.
- Commit exit code (1): fixture hook that exits 1; push-data MUST report "commit refused" and MUST
  NOT push (assert `git rev-parse origin/main` unchanged in the fixture remote). Clean twin: hook
  exits 0, push happens.
- Discard removed (1): dirty `price-history.json` in the fixture; after push-data the working file
  still holds the edit. Clean twin: a clean cloud-owned file is untouched.
- Private index (2): pre-stage a foreign file in the real index of the fixture repo, run the bot
  commit; the commit MUST NOT contain it and the foreign file MUST still be staged afterwards. Clean
  twin: nothing pre-staged, the bot commit is exactly its owned set.
- Hook scope (3): stage a `.ps1` with `GIT_AUTHOR_NAME=smp-pipeline-bot`, commit refused with the
  path named. Clean twin 1: the same staged file as a session author, allowed (verify-bulk-edit still
  runs). Clean twin 2: bot author staging `grocery/out/x.json`, allowed.
- Sweeper audit (5): fixture text `git add -A` -> finding; `git add -A -- grocery/out` -> silent;
  the phrase inside a comment -> silent.

### 4.1 Root cause, one level up

A guard reads its rulings (allowlist, ledger, channel exceptions, rule files) from a fixed path beside
itself, and the harness drives it with a fixture BOARD but not a fixture RULINGS file. The verdict then
depends on two inputs, only one of which is frozen. The hummus case is one instance; the class is
"an input a guard reads by default that the harness did not pin". The rewritten-literal case is the
mirror image: a fixture that IS frozen, but stored as text a mechanical transform cannot tell from code.

## 5. Semantic equivalence of the 608 converted JSON reads

### 5.1 What was measured on this box (PowerShell 5.1, probe script, all cases run)

| shape | `Get-Content -Raw \| ConvertFrom-Json` | `Read-JsonFile` | equivalent? |
|---|---|---|---|
| single-element array, multi array, object | Object[], Object[], PSCustomObject | same (after `return ,`) | yes, verified 09-05 |
| empty file | $null | $null | yes |
| whitespace-only file | $null | $null | yes |
| UTF-16 with BOM | correct (10 chars) | correct (10 chars) | yes |
| BOM-less UTF-8 with U+2019 | mojibake | correct | intended difference (the fix) |
| genuinely cp1252-encoded bytes | correct | U+FFFD in the string, no error | NO: the new reader corrupts silently |
| file another handle holds open for write (share=Read) | reads | THROWS MethodInvocationException | NO |
| relative path after `Push-Location` | resolves against PS location | resolves against process cwd, THROWS | NO |
| missing file, `$ErrorActionPreference = 'Continue'` | continues with $null | TERMINATES the caller | NO, direction: stricter |
| `[` or `]` in the file name | THROWS (wildcard) | reads | difference in the good direction |

And the shapes on disk today (26,573 `.json`/`.jsonl` files under the repo, worktrees excluded):
5,762 pure ASCII, 18,075 UTF-8 with BOM, 2,736 BOM-less non-ASCII UTF-8, 0 invalid UTF-8, 0 UTF-16.
The only `Set-Content`/`Add-Content` writers of a `.json` with no `-Encoding` are 11 fixture lines in
three test scripts, all ASCII content. So the cp1252 class is EMPTY on disk today and the reader must
still refuse it, because the corruption is silent when it does happen.

Call-site census (all 902 Read-JsonFile mentions): 701 bare under EAP=Stop (equivalent: a missing file
threw before too), 115 inside `try`, 35 behind `Test-Path`, 34 bare in files with EAP Continue or unset.
Of those 34, most are libraries whose effective EAP is the caller's. The ones to open:
`health-heartbeat.ps1:32` (expected-automations.json, EAP unset: a missing file now kills the
heartbeat instead of leaving `$cfg` null, and what it did with null before must be read),
`merge-product-urls.ps1:41,62,92`, `multipack-lib.ps1:53` (guard 5's allowlist), `carriage-lib.ps1:103`,
`design-tokens.ps1:54`, `friendly-amt-lib.ps1:47,49,253`, `derived-size-density-lib.ps1:373,427`,
`unit-vocabulary-lib.ps1:92,114`, `ad-match-lib.ps1:90`.
Scripts that call Read-JsonFile AND change location: `check-ad-cycles.ps1`, `ops\verify-bulk-edit.ps1`,
`meal-prep\pipeline\wave-preaudit.ps1`. Each Read-JsonFile argument in those three must be proven
absolute (it usually is: Join-Path from `$root`), or the lib must resolve relative paths itself.
The held-open case matters for `.jsonl` appenders: any reader of `graph\provenance\*.jsonl` or a
capture sink's output while the writer holds the handle now throws where it used to read.

### 5.2 Which other shapes need a parity test, and what the lib should do

1. **cp1252 bytes.** Must-fire: bytes from `GetEncoding(1252)` of a U+2019 string -> `Read-TextFile`
   REFUSES (throws naming the path and the first bad offset), because a U+FFFD in a product name is
   the mojibake class with a different face. Clean twin: the same string as BOM-less UTF-8 reads
   correctly (the existing case 2). Implementation: decode with `UTF8Encoding($false, $true)`
   (throwOnInvalidBytes) when no BOM is present; the current `ReadAllText` default replaces silently.
2. **Held-open file.** Decide the contract: match Get-Content (open with `FileShare.ReadWrite`) so a
   reader never fails on a writer mid-append, or keep the throw and make every jsonl reader retry.
   Recommend matching Get-Content: the old behaviour was the one the estate was built on. Must-fire:
   open a file with `FileAccess.ReadWrite, FileShare.Read` on one handle, `Read-JsonFile` on another
   succeeds. Clean twin: a file opened with `FileShare.None` still throws (exclusive lock is real).
3. **Relative path.** Resolve the argument through `$ExecutionContext.SessionState.Path
   .GetUnresolvedProviderPathFromPSPath` before `ReadAllText`, so PS location semantics are kept.
   Must-fire: `Push-Location <tmp>` then `Read-JsonFile 'x.json'` reads. Clean twin: an absolute path
   is untouched. Second twin: a path with `[` reads (do not route through wildcard-expanding APIs).
4. **Missing file under EAP=Continue.** Keep the throw (fail closed is the estate's rule and the lib's
   case 5 asserts it) and open the 34 sites above individually rather than adding a `-Quiet` switch.
5. **UTF-16 with BOM, empty, whitespace-only**: add as clean twins to the lib's self-test so the
   parity that was measured today stays measured.

### 5.3 Parity at scale

A one-off harness, `ops\json-reader-parity.ps1`: for every `.json`/`.jsonl` under the repo (worktrees
excluded, 26,573 files, minutes not hours), read with both readers, serialise each result with
`ConvertTo-Json -Depth 20 -Compress`, record the type name of the top-level value (array-ness) and
compare bytes. Expected outcome and its positive control: exactly the BOM-less non-ASCII files differ
(2,736 today), and the Campbell's Hy-Vee row must be among them showing mojibake on the OLD side and
U+2019 on the new. Any file that differs for another reason (U+FFFD on the new side, a type-name
change, a throw on one side only) is a finding. A run reporting 0 differences did not run: the 2,736
are known. Run it once now and once after each lib change; the daily `audit-json-readers` ratchet at 0
covers the call sites, this covers the files.

### 5.4 Not proposing, and why

- Making every writer emit a BOM: the header of `json-io.ps1` already rules it out (unenforceable at
  the edges, conflicts with the ASCII pin).
- A `-Raw`-less line-array mode: no converted site was one.
- Swallowing the missing-file throw: fail-open-reads-as-empty is the class the lib exists to end.
